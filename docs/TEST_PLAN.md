## 1. 测试范围与目标

### 1.1 测什么

- 后端：resolver/transcript/extractor/graph 服务、全部 `/api/v1` 接口（含错误码与越权）
- Android：分享接收、悬浮球、结果卡片、列表/编辑、权限引导、音频通道（真机）
- H5：登录、胶囊流、编辑、3D 图谱交互
- 专项：Prompt 提取质量评测集、性能压测

### 1.2 不测什么

- LLM 内容的"正确性"人工逐条评审（只测结构合法率与字段召回率，语义质量靠抽样人评）
- 平台接口本身（B站/抖音 API 属外部依赖，只测我方降级行为）
- iOS / 未在范围平台的浏览器

### 1.3 质量目标

| 目标 | 标准 |
| --- | --- |
| 核心流程 | 分享→胶囊主流程 0 阻断缺陷 |
| 后端单测 | service 层行覆盖 ≥ 60%，全部通过 |
| 提取质量 | AC-03：成功率 ≥ 90%，JSON 合法率 ≥ 90% |
| 接口契约 | API.md 全接口有用例，实际响应与文档 100% 一致 |

### 3.4 专项：Prompt 质量评测（TC-E）

- **数据集**：5 垂类子集（软件操作/装机配置/学习解题/生活技能/理论概念）× 每类 40 条 = 200 条；来源为公开短视频文案（人工脱敏），人工标注"期望主题/变量/步骤要点"作为参考答案
- **指标**：① 提取成功率（产出合法胶囊比例）② JSON 合法率 ③ 字段召回率（steps 覆盖标注要点比例，关键词匹配+人工复核 10% 抽样）④ 平均耗时/Token 成本
- **流程**：脚本批量跑 → 输出按 `prompt_version` × 垂类的分矩阵报告 → 不达标垂类定向改 Prompt → 回归
- **通过标准**：整体成功率 ≥90% 且 JSON 合法率 ≥90%（AC-03），单垂类成功率 ≥80%
- 数据与标注存放 `backend/tests/fixtures/eval/`，不入生产库

## 5. 通过 / 失败标准（发布准出）

- 全部 P0 用例通过，P1 用例通过率 ≥ 95%，无未关闭的致命/严重缺陷
- AC-01 ~ AC-09 全部有对应报告证据（AC-10 为行政产出）
- 回归：任何缺陷修复后必须重跑关联模块用例 + 当次迭代全部 P0 用例

## 6. 缺陷管理与报告

| 等级 | 定义 | 响应时限 |
| --- | --- | --- |
| 致命 | 主流程不可用（提交失败/胶囊丢失/数据越权） | 当天修复 |
| 严重 | 功能不可用但有绕行（如抖音通道全挂走手动） | 2 天内 |
| 一般 | 非核心功能缺陷或体验问题 | 迭代内 |
| 轻微 | 文案/样式问题 | 下个迭代 |

流转：发现 → 群内报单（模板：环境/步骤/预期/实际/截图或录屏）→ 指派 → 修复 → 验证关闭；每周迭代复盘输出缺陷分布（按模块/等级）计入周报。
